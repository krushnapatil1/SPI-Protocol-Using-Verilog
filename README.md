# SPI Protocol Using Verilog HDL

## Overview

This project implements the Serial Peripheral Interface (SPI) protocol using Verilog HDL. It focuses on **SPI Mode 0 (CPOL = 0, CPHA = 0)** and demonstrates serial data communication between an SPI Master and an SPI Slave.

The project includes RTL modules for the master and slave, a top-level module to connect them, and testbenches to verify data transmission and reception.

## Objectives

- Understand the working principle of the SPI communication protocol.
- Implement SPI Master and Slave modules using Verilog HDL.
- Perform 8-bit serial data transmission and reception.
- Verify full-duplex communication between master and slave.
- Simulate and analyze the design using waveform tools.

## Features

- SPI Mode 0 implementation.
- Master and Slave architecture.
- 8-bit data transmission.
- MSB-first data transfer.
- MOSI and MISO serial data lines.
- Full-duplex communication.
- Verilog testbenches for simulation and functional verification.
- Waveform analysis using GTKWave.

## SPI Mode 0

SPI Mode 0 uses the following configuration:

- **CPOL = 0:** The clock is low when idle.
- **CPHA = 0:** Data is sampled on the rising edge and changed on the falling edge of the SPI clock.
- **SCLK:** Serial clock generated by the master.
- **MOSI:** Master Out, Slave In.
- **MISO:** Master In, Slave Out.
- **CS:** Chip Select, active low.

## Simulation

Compile and simulate the master module:

```bash
iverilog -o spi_master_sim spi_master.v tb_spi_master.v
vvp spi_master_sim
```

Compile and simulate the slave module:

```bash
iverilog -o spi_slave_sim spi_slave.v tb_spi_slave.v
vvp spi_slave_sim
```

Compile and simulate the complete master-slave system:

```bash
iverilog -o spi_top_sim spi_master.v spi_slave.v spi_top.v tb_spi_top.v
vvp spi_top_sim
```

Open a generated waveform file in GTKWave, if your testbench creates one:

```bash
gtkwave spi_top.vcd
```

*Note: The simulation commands and waveform filename should match the actual filenames and `$dumpfile` settings in your testbenches.*

## Verification

The testbenches are designed to check the SPI master and slave modules and the integrated communication system.

Verification goals include:

- Checking serial transmission and reception.
- Checking the received data against the transmitted data.
- Observing SCLK, MOSI, MISO, and CS timing.
- Confirming correct operation for SPI Mode 0.
